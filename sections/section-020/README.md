# Detect threats within physical infrastructure, apps, networks, data, users and workloads

The application emits records, but the collector cannot export them. A blank dashboard can describe a telemetry failure while requests continue succeeding.

The explanations identify the responsible components, compare intended and observed state, and work through the decisions needed to preserve the requirement. Each module has a private playground where you run the commands, and one graded lab that practises the skill straight after the part that teaches it.

Read the module landing page, the deep-dive parts and the closing summary in order. A knowledge check of 10 questions follows the summary.

## Learning Path

1. Security Observability And Evidence Quality: signals by layer, workload logs and exit evidence, and evidence gaps.
2. Detecting Risky Workloads From Events, Specifications And Logs: events, risky Pod settings and application log signals.
3. Detecting Threats To Data And User Accounts: ServiceAccounts, Secret access review and Secret exposure paths.
4. Capstone: triage four findings and revoke Secret access.

## Learning Outcomes

- Distinguish API audit, runtime and application security observations.
- Explain telemetry collection and retention trust boundaries.
- Relate alert quality to relevant behaviors and response ownership.
- Identify sensitive fields and evidence gaps.
- Find privileged containers and host directory mounts in Pod specifications.
- Test which accounts can read Secrets and list the paths along which a Secret value can be read.
